# 第一阶段：Markdown 行数与字符数量检查

这是一项**逐作业显式启用**的确定性检查。未配置 `template_metrics`，或配置 `enabled: false`，均保持原有行为；升级审核器不会自动使其他课程启用这项检查。现有 `features.metrics` 是运行指标开关，与本功能无关。

## 以后课程 YAML 怎么写

在 `.github/course-review.yml` 的 `assignments` 下，仅对尚未发布的新作业添加：

```yaml
assignments:
  LabFuture:  # 替换为新作业编号，不能给已经发布的作业追加新限制
    deadline: "2026-11-01T23:59:59+08:00" # 替换为实际截止时间
    report_template: homework/LabFuture/LabFuture.md
    required_files:
      - LabFuture.md
      # 继续列出本次必交的截图等文件
    template_metrics:
      enabled: true
      report_file: LabFuture.md
      characters: ['#', '-', '*', '`', '|', '>']
      max_file_bytes: 200000
    review_points:
      - 在这里填写本次作业的实际验收要求。
    # 原有 vision_files、vision_review_points 等照常配置
```

这是作业配置片段，不要用它覆盖整个课程配置。完整可校验示例见 [examples/template-metrics.yml](../examples/template-metrics.yml)。现有 `version: 1` 无需改变。

| 字段 | 规则 |
|---|---|
| `report_template` | 教师仓库根目录下的 Markdown 模板相对路径；启用时必须配置 |
| `template_metrics.enabled` | 必须显式填 `true` 才启用；省略整个块即关闭 |
| `template_metrics.report_file` | 学生作业目录内的相对路径，必须是 `required_files` 中直接列出的精确 `.md` 文件名，不接受 `one_of` 或通配符 |
| `template_metrics.characters` | 可省略，默认检查 `# - *`、反引号、`| >` 六类；数组不能空、重复或含多字符字符串 |
| `template_metrics.max_file_bytes` | 可省略，默认 200000；范围 1000—1000000；模板和报告分别受限，与 AI 是否启用无关 |

字符可选集合为 `# - *`、反引号、`| > _ [ ] ( ) ! ~ +` 和反斜杠。YAML 中建议像示例一样使用单引号，特别是 `#`、`*`、反引号和反斜杠。

此配置**不能放在 `defaults`、`features` 或 YAML 顶层**，校验会拒绝，以免对其他作业意外生效。第一阶段一个作业指定一份报告，不会把其他文件中的行或符号合并进来。

## 确定的检查口径

先保留原有身份、目录、必交文件等检查；通过后，执行这两项新增检查，最后继续原有 AI 与图片审核。

1. 去掉开头 UTF-8 BOM，将 CRLF、CR 统一为 LF。总行数包含空行；末尾换行只是结束上一行，不额外增加一行。空文件计 0 行。非空行指去掉首尾空白后还有内容的行。
2. 报告总行数、非空行数必须分别不小于模板。任一不足即失败，字符关标记 `NOT_RUN`，不调用后续文本或图片审核。
3. 行数达标后，逐个字符比较数量；每类都必须不小于模板，不能用更多 `#` 补偿少掉的 `*`。数量来自完整 Markdown 源码，包括代码块、命令、日志、HTML 注释中的字符；全角相似符号不能替代 ASCII。
4. 不检查正文总字数、标题数量、代码块闭合或题目是否作答。这些不在第一阶段内。

数量不足返回 `FAIL` 并阻止自动合并，错误包含文件、实际值和模板基准值；行数关通过但字符不足时会列出所有不足的字符。数量通过仅代表通过这两道门槛，不能覆盖后续内容审核失败。

报告超过大小限制或不是有效 UTF-8 文本，返回文件错误。教师模板缺失、空白、无效或超过限制，返回 `CONFIG_ERROR`；学生文件读取时发生 API 故障，返回 `SERVICE_ERROR`。两者均为 `ERROR`，暂停自动合并，不按学生未完成处理。

原有截止时间、超期关闭、AI、双模型分歧及合并策略均保持原样。数量检查失败本身不会要求关闭 PR，原有超期关闭规则仍有效。

## 发布与旧作业兼容

- 已 push 发布的作业不添加此配置，即使以后补交、更新或重跑也继续旧规则。
- 必须先在新模板中声明“题目、说明、示例和选读内容不得删除；选读仍不要求执行或作答”，再与配置一起发布。
- 审核器从 PR 的教师基础分支固定 `base_sha` 读取 `report_template`，绝不使用学生 head 中的模板，也不执行学生文件。检查结果元数据记录模板路径、基础提交 SHA、双方计数及两关状态。
- 发布后保留模板基准稳定。可将发布快照存于 `homework/LabFuture/v1/LabFuture.md`，并让 `report_template` 指向它（保留与学生报告相同的文件名，以兼容现有 AI 模板分段）。不要覆盖发布快照，否则后续 PR 的比较基准会改变。
- 当前实现不会自动推断作业是否已发布，由教师只对新作业显式添加配置。更改已经发布作业的开关会改变它的后续审核，因此应避免这样操作。
- 先将支持这些字段的审核器版本发布并让课程工作流引用，再发布新配置。旧版审核器不认识新字段，会拒绝配置。建议在课程工作流中固定已验证的共享审核器提交 SHA。

本地配置检查：

```bash
course-pr-reviewer validate \
  --config .github/course-review.yml \
  --students .github/students.yml
```

该命令验证 YAML 及字段关系，不联网读取模板。模板存在性、内容与报告数量在实际审核时验证。

## 第二阶段暂不实施

模板结构保留、固定题号、必答清单、字段与占位符检查、逐题 AI 结果校验、图文交叉核对以及分歧策略调整均留待第二阶段。

第一阶段仍可被补无关文字或堆符号绕过，只用于拦截直接大量删减；它也允许原样空模板通过数量门槛，实际是否完成继续由现有内容审核判断。不得把“数量达标”描述成“题目齐全”或“防作弊已经完成”。
